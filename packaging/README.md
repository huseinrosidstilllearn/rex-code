# packaging/ — distribution manifests

winget and Scoop manifests for Rex Code releases, generated by
`generate_manifests.py` (stdlib only — no pip installs needed):

| File | Purpose |
| --- | --- |
| `winget/RexCodeTeam.RexCode.installer.yaml` | winget installer manifest (Inno, x64, machine scope) |
| `winget/RexCodeTeam.RexCode.locale.en-US.yaml` | winget publisher/description/tags |
| `winget/RexCodeTeam.RexCode.yaml` | winget version pointer |
| `scoop/rexcode.json` | Scoop manifest (`innosetup: true` — extracted, never executed) |

Facts are never hardcoded in the generator; it reads them from the repo:

- version ← `rex/__init__.py` (`__version__`)
- ProductCode ← `installer/windows/rexcode.iss` (`AppId` + `_is1` suffix)
- installer URL ← GitHub Releases asset pattern (`RexCode-Setup-v<version>-x64.exe`)
- SHA256 ← `--sha256 <hex>` or `--fetch` (downloads the live release and hashes it)

## Refresh after a release

```powershell
# 1. tag + push (CI builds, attaches artifacts, regenerates, self-checks)
# 2. update the committed manifests from the live release and commit:
python packaging/generate_manifests.py --fetch
python test_packaging.py   # must stay green
git add packaging && git commit -m "chore: manifests for v0.x.y"
```

CI (`.github/workflows/release.yml`, job `distribution-manifests`) already
regenerates and attaches the four files to each tagged release — the step
above just keeps the repo copy in sync for the next `run_all_checks.py`.

## Submitting to the registries (manual, needs a GitHub account)

- **winget**: copy the three YAMLs from the release into
  `microsoft/winget-pkgs` at `manifests/r/RexCodeTeam/RexCode/<version>/`
  and open a PR. Guide: https://aka.ms/winget-pkgs-submit
- **Scoop**: open a PR to `ScoopInstaller/Extras` adding `bucket/rexcode.json`.
  Guide: https://github.com/ScoopInstaller/Scoop/wiki/Creating-an-app-manifest

Code signing (SignPath) is tracked separately; unsigned installers are the
current accepted state (see PANDUAN-INSTALL.md, SmartScreen section).
